Лабораторна робота 4. Реалізація REST-сумісного інтерфейсу до PostgreSQL.
Збережені процедури та тригери
Предметна область: система адміністратора готелю (варіант 1)
 
=====================================================================
ЩО ЦЕ
=====================================================================
 
Проєкт розширює базу даних «Готель» з попередніх лабораторних робіт:
 
  1. Кешування в пам'яті. Дані про номери та кількість вільних місць
     зберігаються в memcached, а nginx віддає їх як REST API (JSON).
     PostgreSQL записує дані в кеш за допомогою розширення pgmemcache.
  2. Тригери синхронізації кешу. Кеш оновлюється після COMMIT; при ROLLBACK
     кеш не змінюється (відкладені тригери-обмеження).
  3. Тригери цілісності. Місткість номера, неперетин періодів проживання
     клієнта, існування поверхів у графіку прибирання.
  4. Збережені процедури операцій адміністратора: поселити й виселити
     клієнта, прийняти й звільнити службовця, змінити розклад прибирання.
  5. Вимірювання ефективності (pgbench).
 
=====================================================================
ВИМОГИ
=====================================================================
 
- Docker Desktop (на Windows потрібен WSL2).
- Python, PostgreSQL, nginx і memcached на комп'ютері встановлювати
  не потрібно: усе працює в контейнерах.
 
Контейнери (docker-compose.yml):
 
  memcached     кеш у пам'яті                  порт 11212
  postgres_db   PostgreSQL 12 + pgmemcache      порт 8432
  nginx         REST API до кешу                порт 8088
  adminer       веб-інтерфейс до бази           порт 8080
 
=====================================================================
ЗАПУСК
=====================================================================
 
1. Відкрити термінал (cmd) у папці проєкту.
 
2. Якщо база вже запускалась раніше, видалити папку postgres\data.
   SQL-файли з postgres\init виконуються лише при першому старті
   ПОРОЖНЬОЇ бази, тому для чистого запуску цю папку треба прибрати
   (команда `compose.bat` її не видаляє).
 
3. Зібрати й запустити контейнери:
      compose.bat
   Це те саме, що: docker-compose -p lab4 up -d --build
   Перший раз виконується кілька хвилин: завантажуються образи.
 
4. Перевірити, що працюють чотири контейнери:
      docker ps
 
5. Увійти в контейнер із базою даних (назву беремо з колонки NAMES):
      bash.bat lab4-postgres_db-1
   і відкрити psql:
      psql -U root -d hotel
 
6. Наповнити кеш (виконується після кожного запуску, бо memcached
   після старту порожній):
      \i /pg/2.sql
 
7. Відкрити в браузері:
      http://localhost:8088/rooms/101
      http://localhost:8088/rooms
      http://localhost:8088/availability
   Для ключа, якого немає в кеші, nginx повертає 404.
 
Вийти: \q (з psql), потім exit (з контейнера).
Зупинити й видалити контейнери: docker-compose -p lab4 down
 
=====================================================================
REST API (nginx -> memcached)
=====================================================================
 
  /rooms/<номер кімнати>   один номер: тип, ціна, місткість, заповненість
  /rooms                   усі номери (масив)
  /availability            кількість вільних номерів і вільних місць
 
Ключ у кеші збігається з адресою запиту. Значення - JSON-документи,
які формує база даних (функції room_json, rooms_json, availability_json).
 
=====================================================================
ПЕРЕВІРОЧНІ СКРИПТИ (postgres/scripts, у контейнері - /pg)
=====================================================================
 
Запуск у psql:  \i /pg/<імʼя>
Усі скрипти після виконання повертають базу в початковий стан,
тому їх можна запускати повторно.
 
  1.sql            перевірка зв'язки: ключ /1 зі значенням hello
  2.sql            наповнює кеш (cache_refresh_all)
  3_1 ... 3_5      тригери кешу: заселення, виселення, ROLLBACK,
                   що було б без відкладення, зміна ціни
  4_1 ... 4_4      тригери цілісності: місткість, зміна типів,
                   періоди проживання, поверхи в графіку
  5_1 ... 5_5      збережені процедури: check_in, check_out,
                   hire_employee, change_schedule, fire_employee
  7.sql            вимірювання ефективності (близько 40 секунд)
  3.sql, 4.sql     те саме, що 3_x та 4_x, одним скриптом
  bench/           файли для pgbench, які використовує 7.sql
 
Скрипт 7.sql тимчасово вимикає тригери для порівняння, а наприкінці
вмикає їх назад і перебудовує кеш. Якщо його перервано, достатньо
запустити 7.sql ще раз.
 
=====================================================================
ЗБЕРЕЖЕНІ ПРОЦЕДУРИ
=====================================================================
 
Поселити клієнта (для нового клієнта додатково вказуються ПІБ і місто):
  CALL check_in('ЕК789012', 102);
  CALL check_in('ЕК000001', 203, p_last_name => 'Іваненко',
                p_first_name => 'Петро', p_city => 'Полтава');
 
Виселити клієнта:
  CALL check_out('ЕК789012');
 
Прийняти службовця на роботу (повертає employee_id):
  CALL hire_employee('Тестенко', 'Оксана', 'Василівна', NULL);
 
Змінити розклад (день тижня 1-7, поверх; без поверху - зняти з дня):
  CALL change_schedule(6, 2, 3);
  CALL change_schedule(6, 4);
 
Звільнити службовця (графік видаляється разом із ним):
  CALL fire_employee(6);
 
=====================================================================
СТРУКТУРА ПРОЄКТУ
=====================================================================
 
  docker-compose.yml, pg-Dockerfile    середовище
  compose.bat, bash.bat                запуск, вхід у контейнер
  nginx/                               конфігурація nginx (custom.conf)
  postgres/init/                       виконується при першому старті бази:
    01_schema.sql                        схема і розширення pgmemcache
    02_data.sql                          тестові дані
    03_cache.sql                         подання room_status, функції кешу
    04_cache_triggers.sql                тригери синхронізації кешу
    05_integrity.sql                     тригери цілісності
    06_procedures.sql                    збережені процедури
  postgres/scripts/                    перевірочні скрипти (див. вище)
 
=====================================================================
ПРИМІТКИ
=====================================================================
 
- Доступ до бази ззовні (DBeaver тощо): localhost:8432, база hotel,
  користувач root, пароль password.
- Adminer: http://localhost:8080, сервер postgres_db, користувач root,
  пароль password, база hotel.
- Папка postgres\data створюється Docker і містить файли бази даних,
  у репозиторій вона не додається (.gitignore).
